1El mapa general

El objetivo: convertir 120 mil filas de ventas en respuestas para la gerencia. Cada programa hace una parte del camino.

🎯 Objetivo del trabajo
Responder 3 preguntas de negocio de Adventure Works (fabricante de bicicletas): qué categorías venden más, qué territorios son rentables y cuáles son los 10 productos estrella.
🧠 Objetivo de aprendizaje
Entender el camino completo de un Datawarehouse: del dato crudo a un cubo multidimensional y a un dashboard que apoya decisiones.
📦 Resultado
Base restaurada, cubo procesado, 8 consultas SQL/MDX, dashboard de 3 páginas, PDF de 47 páginas y repo en GitHub.

2Los 4 conceptos que sostienen todo

Si entiendes estos cuatro, el resto es “solo herramientas”.

① OLTP vs Datawarehouse

La base que usamos (AdventureWorksDW2022) ya es un DW: la “W” significa Warehouse.

② Hechos y dimensiones

Frase clave: medidas son los números; dimensiones son las formas de cortarlos.

③ Cubo OLAP

Es una forma de guardar los hechos ya sumados por cada combinación de dimensiones. Preguntar “ventas de Bicicletas en 2013” es leer una celda, no recorrer 60 mil filas. Lo veremos en la sección 5.

④ Dashboard

Es la pantalla donde el cubo se convierte en gráficos. Un buen dashboard responde una pregunta por visual. Aquí: una página por pregunta de negocio.

3La estructura de la base de datos

AdventureWorksDW2022 tiene 31 tablas. Usamos 7. Este es el modelo en estrella (con una rama “copo de nieve” en Producto).

🔑 Llaves
ProductKey, OrderDateKey, SalesTerritoryKey son números que “apuntan” a la dimensión. Es como un carné: la venta no guarda el nombre del producto, guarda su número.
📐 Utilidad
No existe como columna. La calculamos: SalesAmount − TotalProductCost. Por eso la creamos como medida calculada en el cubo.
🔍 Hallazgos de calidad
Datos de dic-2010 a ene-2014 (años incompletos). 209 productos sin subcategoría, pero ninguno con ventas, así que no estorban.

4Qué es cada programa y para qué se usó

Dos servidores (guardan y calculan) y varios clientes (los usas para pedirles cosas).

SERVIDOR

SQL Server 2025 Developer

Qué es
El programa que guarda las tablas y responde consultas SQL. Corre como servicio de Windows, siempre encendido.
Para qué lo usamos
Aquí se restauró AdventureWorksDW2022 y de aquí lee el cubo sus datos.
CLIENTE

SSMS (SQL Server Management Studio)

Qué es
Ventana gráfica para hablar con SQL Server: escribes una consulta, pulsas Execute, ves el resultado.
Para qué lo usamos
Ejecutar el script de restauración, explorar tablas y correr las consultas SQL de las 3 preguntas (capturas del PDF).
CLIENTE

sqlcmd

Qué es
La misma idea que SSMS, pero en la consola: sqlcmd -S localhost -i script.sql.
Para qué lo usamos
Comprobar rápido datos y verificar que SQL y MDX dan las mismas cifras, sin abrir ventanas.
SERVIDOR

SQL Server Analysis Services (SSAS)

Qué es
Un segundo servidor, especializado en cubos. Toma los datos de SQL Server, los pre-calcula por dimensiones y los guarda en formato multidimensional. Se le consulta con MDX.
Para qué lo usamos
Aquí vive el cubo Ventas AdventureWorks. Modo elegido: Multidimensional.
DISEÑO

Visual Studio 2022 + “Analysis Services Projects”

Qué es
Visual Studio es un entorno de programación. La extensión (llamada SSDT) le añade el tipo de proyecto “Analysis Services”: un cubo se vuelve una carpeta con archivos que puedes editar y guardar en Git.
Para qué lo usamos
Ver y documentar el cubo con sus diseñadores (abajo) y comprobar que el proyecto compila.
VISUAL

Power BI Desktop

Qué es
Programa de Microsoft para crear dashboards: gráficos, tablas, tarjetas, filtros.
Para qué lo usamos
Conectarlo en vivo al cubo y mostrar las respuestas. Guarda todo en un archivo .pbix.
CÓDIGO

PowerShell + AMO + ADOMD.NET

Qué es
PowerShell es la consola con scripts de Windows. AMO es una librería para crear objetos de Analysis Services por código. ADOMD.NET es la librería para consultarlo con MDX.
Para qué lo usamos
Construir el cubo con un script repetible (30-build-cube.ps1) y ejecutar las consultas MDX (42-show-mdx.ps1).
ENTREGA

Python, Pillow, WeasyPrint, Git y GitHub

Qué es
Python con Pillow dibuja los círculos y flechas en las capturas. WeasyPrint convierte HTML en PDF. Git/GitHub guardan la historia del proyecto.
Para qué lo usamos
Anotar las capturas, generar el PDF de 47 páginas y publicar el repositorio.
APOYO

winget, Microsoft Store, UI Automation

Qué es
winget instala programas por comando. UI Automation es la API de Windows con la que un programa “ve” y pulsa botones de otras ventanas.
Para qué lo usamos
Instalar Power BI y manejar las ventanas para tomar las capturas automáticamente.

5Cómo funciona el cubo

Un cubo tiene ejes (dimensiones) y en cada celda hay una medida ya calculada.

🎮 Juega con el cubo (cifras reales)

Elige un año y una categoría: el cubo “devuelve” la celda y se muestra la consulta MDX equivalente.

—






Jerarquías: bajar y subir de nivel (drill)





Medidas: de dónde salen los números



Sumas (azul/amarillo) las guarda el cubo. Cálculos (verde) se definen en MDX y se resuelven al consultar.








6El algoritmo, paso a paso


Esto es exactamente lo que hicimos, en orden. Cada paso tiene su “por qué” y su comando.








Paso 1 · Preparar el entorno una vez

Instalar SQL Server (motor), Analysis Services, Visual Studio con la extensión, SSMS y Power BI. Ver sección 9.
Por qué: sin el servidor OLAP no hay dónde guardar el cubo; sin la extensión, Visual Studio no sabe abrir proyectos de cubos.



Paso 2 · Restaurar la base SQL Server

El .bak es una “foto” de la base. Restaurar = convertir esa foto en una base viva dentro de tu servidor.


RESTORE DATABASE AdventureWorksDW2022
FROM DISK = 'C:\Users\Public\dp2\AdventureWorksDW2022.bak'
WITH MOVE 'AdventureWorksDW2022'     TO '…\DATA\AdventureWorksDW2022.mdf',
     MOVE 'AdventureWorksDW2022_log' TO '…\DATA\AdventureWorksDW2022_log.ldf', REPLACE;


Por qué MOVE: el respaldo trae rutas de otra máquina; con MOVE le dices dónde guardar los archivos en la tuya. SQL Server además “actualiza” la base a su versión (en pantalla: version 957 → 998).



Paso 3 · Explorar y elegir tablas SSMS

Se cuentan filas de cada tabla, se revisan llaves y calidad. De 31 tablas se eligen 7 según lo que piden las preguntas.

Paso 5 · Procesar y consultar SSAS

Procesar = SSAS lee SQL Server, suma por cada combinación de dimensiones y guarda el resultado. Después de procesar, el estado es Processed y ya se puede consultar con MDX.


// 1) AMO crea y procesa
$db.Process([ProcessType]::ProcessFull)
// 2) ADOMD consulta
SELECT [Fecha].[Año-Trimestre-Mes].Levels(1).MEMBERS ON COLUMNS, ...



Paso 6 · Dashboard en Power BI Power BI

Get data → SQL Server Analysis Services database → Connect live. Después, cada visual es un “campo del cubo” (por ejemplo Fecha.Año + medida Total Ventas). Ver sección 8.



Paso 7 · Documentar y entregar Python / Git

Capturas → anotarlas (círculos y flechas) → PDF → repositorio. Todo con scripts para poder repetirlo si algo cambia.








7La misma pregunta en SQL y en MDX


Pregunta 3: “¿Cuáles son los 10 productos más rentables?”




SQL · sobre las tablas

SELECT TOP (10) p.EnglishProductName,
       SUM(v.SalesAmount - v.TotalProductCost) AS utilidad
FROM (SELECT ProductKey, SalesAmount, TotalProductCost
      FROM FactInternetSales
      UNION ALL
      SELECT ProductKey, SalesAmount, TotalProductCost
      FROM FactResellerSales) v
JOIN DimProduct p ON p.ProductKey = v.ProductKey
GROUP BY p.EnglishProductName
ORDER BY utilidad DESC;


Tú le dices cómo: unir, agrupar, sumar, ordenar.


MDX · sobre el cubo

SELECT
 { [Measures].[Utilidad Total],
   [Measures].[Total Ventas] } ON COLUMNS,
 TOPCOUNT(
   NONEMPTY([Producto].[…].Levels(3).MEMBERS,
             [Measures].[Utilidad Total]),
   10, [Measures].[Utilidad Total]) ON ROWS
FROM [Ventas AdventureWorks]


Tú le dices qué ejes quieres; el cubo ya sabe sumar.








Para qué hacer las dos: si SQL y MDX coinciden, el cubo está bien construido. Es una “prueba de cordura”.








8Power BI: conexión en vivo vs importar




🔴 Connect live (lo que usamos)



No copia datos. Cada gráfico hace una consulta al cubo. Siempre ves lo último. El modelo (medidas, jerarquías) vive en el cubo, no en Power BI.


⚪ Import (no usado)



Copia los datos dentro del .pbix. Es más rápido sin conexión, pero se desactualiza y duplica el modelo. El desafío pedía conectar al cubo, por eso usamos live.




Qué hay dentro del archivo .pbix



Lo descubrimos guardando un visual de prueba y leyendo el archivo: un .pbix es un zip con JSON. Así pudimos generar las 3 páginas por código.








9Cómo descargar e instalar todo, paso por paso


Dos caminos: el comando (lo que hicimos) y el mouse (lo que harías a mano).



1
La base de datos (.bak)


Descarga AdventureWorksDW2022.bak de github.com/Microsoft/sql-server-samples/releases/tag/adventureworks (sección “Data Warehouse”). Pesa unos 97 MB. Elige el año compatible con tu SQL Server.


Invoke-WebRequest "…/AdventureWorksDW2022.bak" -OutFile C:\Users\Public\dp2\AdventureWorksDW2022.bak


Déjalo en una carpeta que el servicio de SQL Server pueda leer. Si lo dejas en tu Escritorio, el servicio no tiene permiso.



2
SQL Server 2025 (motor) + SSMS


Descarga SQL Server 2025 Developer (gratis, uso de aprendizaje) del sitio de Microsoft y ejecuta el instalador. Con el mouse: Custom → New SQL Server stand-alone → Database Engine Services. Instala también SSMS.


winget install Microsoft.SQLServer.2025.Developer
winget install Microsoft.SQLServerManagementStudio



3
Analysis Services en modo Multidimensional


Es una característica más del instalador de SQL Server. Con el mouse: Installation → New SQL Server stand-alone or add features → Analysis Services → modo “Multidimensional and Data Mining”. Por comando (pide permiso de administrador/UAC):


SETUP.EXE /Q /ACTION=Install /FEATURES=AS /INSTANCENAME=MSSQLSERVER ^
  /ASSERVERMODE=MULTIDIMENSIONAL ^
  /ASSYSADMINACCOUNTS="TU-PC\tu-usuario" ^
  /IACCEPTSQLSERVERLICENSETERMS


Resultado: aparece el servicio MSSQLServerOLAPService en estado Running.



4
Visual Studio 2022 + extensión


Instala Visual Studio 2022 Community. Luego añade la extensión Analysis Services Projects: en Visual Studio, Extensions → Manage Extensions → buscar “Analysis Services Projects” → Download; se instala al cerrar. (Nosotros bajamos el .vsix del Marketplace e instalamos con VSIXInstaller.exe /quiet.)



5
Power BI Desktop


winget install --id 9NTXR16HNW1T --source msstore


o desde la Microsoft Store: buscar “Power BI Desktop”. Es gratuito.



6
Comprobar que todo funciona


Get-Service MSSQLSERVER, MSSQLServerOLAPService   # deben decir Running
sqlcmd -S localhost -E -C -Q "SELECT @@VERSION"


-C significa “confío en el certificado”: tu servidor local usa uno autofirmado y sin esa opción el cliente lo rechaza.

10Las dificultades que aparecieron (y cómo se resolvieron)


En proyectos reales casi nada funciona a la primera. Esto es lo valioso: el síntoma → causa → arreglo.




Nombres con tilde salían corruptos (Categor��a)
Causa: Windows PowerShell 5.1 lee un .ps1 sin BOM como ANSI. Arreglo: guardar los scripts con BOM UTF-8.


El cubo procesaba mal: “la llave de atributo no se encuentra”
Causa: 209 productos sin subcategoría (nulos). Arreglo: miembro desconocido “Sin asignar”. (Luego comprobamos que no tienen ventas.)


MDX fallaba: “LEVELS espera una jerarquía”
Causa: los nombres con tilde estaban corruptos (el problema anterior) y la dimensión y un atributo se llamaban igual. Arreglo: BOM + renombrar el atributo.


Los trimestres salían solo como “1, 2, 3, 4”
Causa: ambiguos entre años. Arreglo: columna calculada “2013 T1”; así ordena cronológicamente como texto.


Visual Studio se colgaba sin mostrar nada
Causa: una ventana de inicio de sesión (bloqueante) que no se veía en modo comando. Arreglo: abrir con interfaz y pulsar “Skip and add accounts later”. Después, una encuesta “User Feedback” bloqueaba la interfaz.


El despliegue desde Visual Studio falla
Causa: “edición StandardDeveloper64 no soportada por el cliente”: la extensión es anterior a SQL Server 2025. Arreglo: desplegar con AMO (mismo resultado). Se documentó con honestidad en el PDF.


SSMS no aceptaba -E y rechazaba el certificado
Causa: SSMS 22 cambió su línea de comandos y exige cifrado. Arreglo: sin -E y marcar “Trust Server Certificate”.


Power BI: “el archivo está corrupto” al abrir el .pbix generado
Causa: el archivo SecurityBindings es una firma del contenido. Arreglo: omitirlo; Power BI lo regenera al guardar.


El filtro “Top 10” de Power BI se ignoraba en silencio
Causa: formato de filtro no reconocido. Arreglo mejor: hacerlo en el cubo: conjunto “Top 10 Productos” + medidas “Utilidad Top 10” y “Ventas Top 10”.


Las tablas anchas se partían en la consola
Causa: Windows Terminal ignora el tamaño de ventana. Arreglo: consola clásica y mostrar los trimestres en bloques de 7.


Se fue la luz a mitad de la tarea
Arreglo: como todo estaba en scripts y en disco (servicios automáticos, cubo ya procesado), se retomó sin repetir el trabajo.


Lección general
Automatizar (scripts) hizo que cada error se arreglara una vez y se pudiera repetir todo. Eso es lo que separa un trabajo manual frágil de uno reproducible.










11Qué aprendiste (objetivos de aprendizaje)

12Glosario rápido




Datawarehouse (DW)
Base de datos preparada para analizar historia, no para registrar ventas del día a día.


Tabla de hechos
Tabla con lo que se mide (monto, costo, cantidad). Una fila por evento.


Dimensión
Tabla que describe los hechos (fecha, producto, territorio).


Llave sustituta (key)
Número que une un hecho con su dimensión (ProductKey).


Esquema en estrella / copo de nieve
Hechos al centro y dimensiones alrededor; copo de nieve cuando una dimensión se parte en varias tablas (Producto → Subcategoría → Categoría).


Cubo OLAP
Estructura que guarda las medidas ya sumadas por cada combinación de dimensiones.


Atributo / jerarquía / nivel
Atributo: una columna útil (Año). Jerarquía: un camino ordenado de atributos (Año ▸ Trimestre ▸ Mes). Nivel: cada escalón.


Medida / grupo de medidas
Medida: número que se suma. Grupo de medidas: las medidas que vienen de una misma tabla de hechos.


Medida calculada
Número que se obtiene con una fórmula MDX sobre otras medidas (Utilidad = Monto − Costo).


Procesar
Leer los datos de origen y llenar el cubo.


Desplegar (deploy)
Enviar la definición del cubo al servidor.


MDX
Lenguaje para consultar cubos (como SQL, pero con ejes y celdas).


T-SQL
El SQL de SQL Server.


Conexión en vivo
Power BI consulta la fuente cada vez, sin guardar una copia.


AMO / ADOMD.NET
Librerías de .NET para crear (AMO) y consultar (ADOMD) Analysis Services por código.


SSDT
Herramientas de datos de SQL Server para Visual Studio: lo que añade el tipo de proyecto “Analysis Services”.
